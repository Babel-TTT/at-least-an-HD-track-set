# 建模标准 —— 让任何 agent 都能接手的规矩

> 这份管**规矩**：什么必须做、什么禁止做、怎么算做完。
> 手艺看 skill `flatiso-model-authoring`；坐标口径看 `docs/定标.md`；用词看 `docs/术语表.md`；
> 路线与阶段看 `实现计划.md`。
>
> **规矩都要能回答"为什么"和"哪次踩的"。** 没有理由的规矩，agent 会自己找借口绕过去。

## 1. 铁律（无例外）

### L1 读 OpenTTD 游戏代码之前必须先申请

- **规矩**：任何 agent（含子代理）在打开 `OpenTTD-HankPP` 等 C++ 源码树**之前**先向人工申请。先问再做，不是读完再报告。
- **申请要写清三件事**：读哪个文件/目录、要回答什么问题、为什么非它不可（参考 GRF / 文档 / 实机观察能不能替代）。
- **为什么**：这些树各 2000~3700 个文件，无边界 grep 极易烧干上下文；而多数答案本来就能从参考包 / wiki / 实机观察拿到。
- **哪次踩的**：曾有三个子代理同时被派去查同一件引擎规格，其中一个自行钻进 C++ 树，白白消耗。

### L2 查游戏机制的 NML 实现，先读官方 wiki

- **顺序固定**：① <https://www.tt-wiki.net/>（镜像 `newgrf-specs.tt-wiki.net`）→ ② 本地参考 GRF → ③ C++ 源码（需先申请）。
- **回报时写明是哪一页**，方便复核。
- **哪次踩的**：跳过 wiki 直奔 C++，浪费一轮。

### L3 写任何脚本之前必须先申请

- **范围**：`tools/*.mjs`、`out/*.mjs`、`Makefile` 目标、任何 `.ps1`/`.py`/`.sh`。
- **申请要写清**：脚本路径与用途、会改哪些文件、为什么非用脚本不可（能不能用 `edit`/`write` 直接改）。
- **理由**：脚本会**批量、静默**地改源文件。本工程已经因此把 `src/rails/templates.pnml` 反复改坏：遗留的【手调】增量被当成基准滚雪球、几何改动导致格位变化而 rect 未同步。
- **例外（人工裁定）**：`tools/gen-*.mjs` 是**模型生成器**，可以直接改。隧道模型有 600+ 个 quad，坐标全是算出来的，手写不现实；生成的 `.model` 仍是一行行写死的字面量，只是"写字面量"这步由脚本代劳。**新增脚本、以及 `tools/` 下非生成器的脚本，仍然要先申请。**

### L4 `src/rails/templates.pnml` 是人工的文件

- **只有新增精灵类型时才允许改**，而且**只能人工手改**，任何脚本不得写入。
- 有意偏离算法值的行，注释里写 **`【手调】`**，`make check` 就不再报它。
- **哪次踩的**：`sync-templates.mjs` 把一条遗留的手调增量当基准滚雪球，把 rect 写坏导致 `nmlc` 报 `Read beyond bounds of image file`。详见 `docs/踩坑.md`。

### L5 用词以 `docs/术语表.md` 为准，不确定就问

- 人工说一个构件名，先去表里查代码标识符。**表里没有的，先问，不要猜。**
- **哪次踩的**：把「侧面」当成「斜面」删错一轮；「顶坡」不确认又来回两轮。每次都是一次全量重建加一次实机核对。

### L6 所有决定都要人工审批

- 遇到难解的问题**等人工修复**，遇到不了解的问题**等人工回答**。
- 工作定位：**不求完美，先搭框架和建模生成**。
- **不要以任何理由推辞**，也不要因为"上下文要满了"就停下——历史会自动压缩，继续在同一个会话里做。

### L7 渲染器核心不能随便改

- `flatiso/core/` 下的 `raster.mjs` / `look.mjs` / `grade.mjs` / `grain.mjs` / `project.mjs` 改动**必须先问**。
- 本工程对 flatiso 的改动**严格限定**在已批准的那几处（见 `实现计划.md` §5）。

### L8 改源文件用 `edit`/`write` 工具，禁止 PowerShell 批量读写

- **为什么**：PS 5.1 默认按 ANSI 读，会把 UTF-8 中文写成乱码。`make check` 的编码自检**抓不到**所有情况。
- **哪次踩的**：`Set-Content` 把 `tools/gen-g1-tunnel.mjs` 的中文写成 `?`、换行被吃掉，直接 `SyntaxError`，只能 `git checkout` 回滚。

### L9 改完 GRF 必须重启 OpenTTD

- OpenTTD 在启动时读 GRF 并缓存精灵。**只覆盖文件、不重启，看到的还是上一次的精灵。**
- 人工报"改了没反应"时，第一句先确认重启过。

## 2. 完成定义（固定命令链，顺序不能换）

```
node tools/gen-g1-tunnel.mjs          # ① 生成模型（改了生成器就必须跑）
node tools/build.mjs --step render    # ② flatiso 渲染 → gfx/
node tools/build.mjs                  # ③ nmlc 编译 → out/china-style-track.grf
node tools/check.mjs                  # ④ 自检，必须全过
cp out/china-style-track.grf <OpenTTD>/newgrf/    # ⑤ 同步给人工实机
```

**⚠ 第 ① 步最容易漏。** `--step render` **不会**重新生成模型；改了生成器却不跑 ①，等于什么都没改——本工程因此得出过一次错误的"像素没变"结论。

**判据**：
- ④ 必须 `✔ 全部通过`
- 改了几何 → 必须重出 `out/tunnel-composite.png` 之类的对照图，**给人工看图，不要给坐标**（人工不读坐标）
- 临时诊断脚本/模型用完**当轮删掉**（`out/*.mjs` 除外，它本来就不入库）

## 3. 验收判据（把"差不多"改成"跑什么、看到什么算过"）

| 阶段类型 | 判据 |
|---|---|
| 模型几何 | 4 个朝向逐一看过；`make check` 通过；`out/atlas/*contact.png` 无破面/穿帮 |
| 图层接入（NML） | `nmlc` 无 error；精灵张数与 spriteset 槽位数一致；实机四个朝向都看过 |
| 修 bug | **先说清根因**（能复现、能证伪的猜测要列出来并逐个排除），再改；改完给改前/改后两张图 |
| 加新精灵类型 | `templates.pnml` 由**人工**加；`make sprites` 对账一致；`make check` 通过 |

**修 bug 的纪律**：本工程在隧道上连续两次把"看起来像的原因"当成原因（"50° 面在 30° 镜头下是细条"、"抬高 WING_Z0 会毁掉护坡"），都靠**单变量对照实验**才推翻。**不要发明机制，做对照实验。**

## 5. 外部依赖与打包

**2026-10-01 起：clone 本仓库就能跑，不需要再去找第二个仓库。** 渲染器已内置。

| 依赖 | 现状 | 说明 |
|---|---|---|
| **flatiso（渲染器）** | **已内置** —— `tools/flatiso/`（vendored 快照，源 commit `8720126`） | 见 `tools/flatiso/VENDORED.md`。默认 `FLATISO = tools/flatiso` |
| **nmlc** | **从系统 PATH 取** | `NMLC ?= nmlc`，装好放进 PATH 即可；版本 0.9.0 验证过 |
| **gcc** | 从系统 PATH 取 | nmlc 不带预处理器，`.pnml` 必须先过 `gcc -E` |
| **Node ≥ 18** | 装就行 | 纯 Node ESM、零第三方依赖，不需要 `npm install` |

**覆盖面（改之前）**：`Makefile.config` 里写的是**作者本机**的绝对路径
（一个指向作者自己那台机器上 flatiso 仓库的盘符路径，以及 `nmlc` 的安装位置）——
**别人 clone 下来 `make render` 直接失败**（`找不到 flatiso 构建入口`）。

**优先级**：环境变量 > `Makefile.config` > 默认值。想用外面的 flatiso 调试：

```powershell
$env:FLATISO = '<flatiso 仓库所在路径>'
node tools/build.mjs --step render
```

**踩坑记录（这次改的时候踩到的）**：把 `NMLC` 从绝对路径改成光名字 `nmlc` 之后，
构建报 `❌ 找不到 nmlc：nmlc` —— 因为 `tools/build.mjs` 用的是 `fs.existsSync(cfg.nmlc)`，
那是按**当前工作目录**找的，光给名字永远找不到。已在 `tools/util.mjs` 加 `which()`：
**先在 `PATH` 上解析成绝对路径**，带路径分隔符的值原样返回（老写法照样能用）。

**`tools/flatiso/` 的两条规矩**：
1. **不要在里面做长期开发** —— 改了不会回流上游，下次同步就丢。要改渲染器去上游改。
2. 本工程**没有**改过 `tools/flatiso/core/` 下的任何文件（铁律 L7）。
3. 自检（`tools/check.mjs`）**整棵跳过 `tools/flatiso/`** —— 那是上游第三方文件，
   它自带几个带 BOM 的文件，不该由本工程的自检去管。

**同步方式**（要更新快照时）：

```powershell
robocopy <flatiso 仓库> tools/flatiso /E /XD .git out
# 然后更新 tools/flatiso/VENDORED.md 里的「源 commit」
```

## 7. 与其他 agent 协作时的最小检查单

接手前：
1. 读 `docs/术语表.md`（用词）→ `docs/建模标准.md`（本文，规矩）→ `实现计划.md` §2/§4（路线）。
2. 跑一遍 §2 的固定命令链，确认**改动之前**就已经通过——否则你分不清是你改坏的还是本来就坏的。
3. 明确这一轮只做哪**一件**事。

交付时：
1. 固定命令链全过。
2. 给人工**图**，不给坐标。
3. 说清：改了什么、为什么、验证方式、还剩什么没验证。
4. 产生了新裁定 → 回写本文 §4；产生了新叫法 → 回写术语表；路线变了 → 回写 `实现计划.md`。
