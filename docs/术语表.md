# 术语表 —— 人工用词 ↔ 代码标识符

> **这份表放在最前面看。** 本项目最大的返工来源不是"不会做"，而是**叫法对不上**：
> 曾经把「侧面」当成「斜面」删错一轮；「顶坡」不确认又来回两轮。
>
> **规矩：人工在对话里用的词，一律以本表为准。表里没有的，先问，不要猜。**

---

## 0. 怎么用

1. 人工说一个词 → 到「§1 洞口构件」或「§2 工序与缺陷」里查 → 拿到代码标识符 → 直接去改对应函数。
2. 改完之后，**如果产生了新的叫法，回来补一行**。
3. **划掉的行不要删。** 那是"已经否决过的方案"，留着才能挡住下一个 agent 重新发明。

### 1.1 隧道口的四个模型（人工裁定：总共四个模型就够了）

| 组 | 模型 | 用在哪 | 拱腹可见弧 |
|---|---|---|---|
| **A** | `G1_tunnel_stone` / `G1_tunnel_stone_over` | 槽 0（v0=NE）、槽 1（v3=SE） | **−y 侧** |
| **B** | `G1_tunnel_stone_b` / `G1_tunnel_stone_over_b` | 槽 2（v2=SW）、槽 3（v1=NW） | **+y 侧**（镜像） |

- `_over` 结尾的 = `tunnel_overlay:` 组（画在**车之上**）；不带的是 `tunnels:` 组（画在车之下）。
- **近半进 overlay、远半进 tunnels** —— 靠 `splitByY()` 按顶点平均 y 切。哪半边"近"**逐朝向不同**，所以需要 A/B 两套。
- `G1_tunnel_frame.model` 是**哨兵模型**（无几何、`zmax 0.7000`），只为把隧道那格的格位尺寸钉死在 263×181，不参与取图。

## 2. 工序、缺陷、口头绰号

| 人工用词 | 指什么 | 备注 |
|---|---|---|
| **手性** / 左右 | `splitByY()` 的切分 + A/B 两组模型 | 人工原话："隧道口一般只有半边图像来遮盖车辆" |
| **碎** / **破碎** | 洞口外立面看起来一把梳子 / 一堆小三角没渲染 | 已定位过**两种**独立成因，见下 |
| **锯齿** / **透明模糊** | 曲面在临界角附近表现为毛边 | 见下 |
| **穿帮** | 能看到本该被挡住的东西（背后/底下） | — |
| **实机** | 装进 OpenTTD 里看，不是看 flatiso 出的图 | 改完 GRF 必须**重启** OpenTTD 才会重读 |
| **格位** | 图集里一格的大小（本项目隧道 = 263×181） | 由 `unionFrame` 决定，受 `zmax` 影响 |
| **哨兵** | 无几何、只为钉住格位的模型 | 见 §1.1 |
| **对账** | `make sprites` / `make check` 拿图集和 `templates.pnml` 比 | 有意偏离的行要标【手调】 |

### 2.1 「碎」的两种已知成因（都修过了，别退回去）

| 成因 | 症状 | 根因 | 修法 |
|---|---|---|---|
| **条带塌陷** | 洞口外立面大片小三角缺失 | 腹墙条带的取点被钳到拱心：`archZ(Math.min(y0+1e-6, ARCH_CY))` —— 而 `archZ(拱心)` 恰好 = 拱顶，于是右半的 `z0`、左半的 `z1` 全塌到拱顶，每条带只剩一根细三角 | 直接用 `archZ(y0)` / `archZ(y1)`，**不要钳** |
| **法线退化** | 少数面消失 | `q4o()` 原来用「前三点叉积」定法线；三点共线时叉积为 0 ⇒ 判不出绕序 ⇒ 不翻绕序 ⇒ 整批被判成背面剔掉 | 法线改用 **Newell 法**（对全部顶点求和），对重复顶点/共线不退化 |

> 另有两个已排除的猜测：**不是**抗锯齿，也**不是**背面剔除。
> 证据：`--no-cull` 重渲染锯齿依旧（⇒ 与剔除无关）；`--ss 1` 关抗锯齿后锯齿更清楚（⇒ 与 AA 无关）。

## 3. 维护约定

- 新造的词、新的简称，**当天补进本表**，不要只留在对话里。
- 人工在对话里纠正过叫法的（例如"你删了侧面没删斜面"），把**两种叫法都记下来**，并注明哪个是人工的口径。
